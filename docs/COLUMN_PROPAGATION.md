# COLUMN_PROPAGATION.md

## Назначение

Документ описывает две взаимосвязанные фичи в полном режиме Column Lineage:

1. **«Протянуть колонку»** — проброс отдельной колонки из родительской таблицы в дочернюю через контекстное меню (ПКМ)
2. **«Протянуть таблицу в следующий слой»** — создание новой дочерней таблицы жестом drag-and-drop за заголовок карточки

**Общие ограничения обеих фич:**
- Все изменения временные (UI-only)
- Не сохраняются при обновлении страницы
- Не пишутся в backend или базу данных

---

# Фича 1: «Протянуть колонку»

## Цель

- Позволить пользователям быстро добавлять колонку из родительской таблицы в дочернюю
- Визуализировать добавленные колонки с подсветкой
- Создавать временные связи между таблицами
- Обеспечить вертикальное перемещение добавленных колонок

---

## Условия проброса

Кнопка "Протянуть колонку" отображается в контекстном меню только если **ВСЕ** условия выполнены для дочерней таблицы:

### 1. Один родитель
```javascript
// У дочерней таблицы должен быть ровно один upstream
info.lineage.upstream.length === 1
```

### 2. Наличие скрипта (только для реальных таблиц)
```javascript
// У дочерней таблицы должен быть скрипт в public.sql_inventory
// Условие ПРОПУСКАЕТСЯ для виртуальных таблиц (_isVirtual === true)
info.sql_script && info.sql_script.trim().length > 0
```

### 3. Отсутствие GROUP BY (только для реальных таблиц)
```javascript
// В скрипте дочерней таблицы не должно быть GROUP BY
// Условие ПРОПУСКАЕТСЯ для виртуальных таблиц (_isVirtual === true)
!/GROUP\s+BY/i.test(info.sql_script)
```

Если хотя бы одно применимое условие не выполнено, кнопка не отображается и показывается оповещение с причиной.

> **Виртуальные таблицы.** Для таблиц, созданных через «Протянуть таблицу»
> (`_isVirtual: true` в объекте из `__tablePropagationState.virtualTables`),
> проверяется только условие 1. У виртуальной таблицы нет собственного
> `sql_script` — скрипт генерируется динамически (`generateModifiedSql`),
> поэтому условия 2 и 3 к ней неприменимы.

## Логика работы

### Контекстное меню

При нажатии ПКМ на колонку в полном режиме Column Lineage:

1. **Определяем родительскую таблицу** (текущая таблица, на которой ПКМ)
2. **Ищем дочерние таблицы** (downstream)
3. **Проверяем условия** для каждой дочерней таблицы
4. **Формируем контекстное меню:**
   - **0 подходящих таблиц:** показываем сообщение "Нет подходящих таблиц для проброса"
   - **1 подходящая таблица:** показываем кнопку "Протянуть колонку"
   - **Несколько подходящих таблиц:** показываем чекбоксы для выбора таблиц

### Добавление колонки

При нажатии на кнопку "Протянуть колонку":

1. Создаём элемент колонки в DOM дочерней таблицы
2. Добавляем специальные атрибуты:
   - `data-propagated="true"` — маркер пропагированной колонки
   - `data-propagated-from="parentTableId"` — источник
3. Применяем стили подсветки (фиолетовый градиент)
4. Добавляем кнопки редактирования алиаса (✏️) и удаления (✕)
5. Сохраняем состояние в `window.__propagationState`
6. Создаём ребро связи с родительской таблицей
7. Показываем оповещение об успехе
8. **Drag-and-drop**: колонку можно перетаскивать ЛКМ вверх/вниз (cooldown 150мс между перемещениями)

### Перемещение колонки

Колонка перемещается при перетаскивании ЛКМ:

1. Удерживайте левую кнопку мыши на пропагированной колонке
2. Двигайте мышь вверх или вниз
3. При сдвиге мыши на половину высоты колонки от её центра — колонка перемещается на одну позицию
4. Перерисовка рёбер происходит автоматически через событие `propagation-update`
5. Cooldown 150мс предотвращает подрагивания при быстром движении мыши
6. Состояние сохраняется только в DOM

## Структура данных

### Состояние проброса

```javascript
window.__propagationState = {
  propagatedColumns: Map<uniqueId, Set<columnKey>>,   // Какие колонки добавлены
  propagationEdges: Map<edgeKey, edgeInfo>,             // Информация о рёбрах
  menuElement: HTMLElement | null,                     // Текущее контекстное меню
  currentMenuTarget: HTMLElement | null,               // Целевой элемент
}
```

**Ключи:**
- `uniqueId` — уникальный идентификатор вкладки (например, "DWH-dds-account_detail")
- `columnKey` — "tableId.columnName" (в нижнем регистре)
- `edgeKey` — "prop-parentTableId-childTableId-columnname"

### Информация о ребре

```javascript
{
  parentTableId: string,   // ID родительской таблицы
  childTableId: string,    // ID дочерней таблицы
  columnName: string,      // Имя колонки
  uniqueId: string,        // ID вкладки
}
```

## Интеграция с Column Lineage

### Инициализация

В `columnLineage.js`, функция `renderColumnLineage()`:

```javascript
import { 
  initPropagation, 
  cleanupPropagation, 
  getPropagationEdges, 
  getPropagatedColumns 
} from "./columnLineagePropagation.js";

// Очистка при рендере
cleanupPropagation(uniqueId);

// Инициализация
initPropagation(uniqueId, getTableInfo, displayedTables);

// Слушаем события обновления
const handlePropagationUpdate = (e) => {
  if (e.detail?.uniqueId === uniqueId) {
    drawLinesLocal();
    drawPropagationEdgesLocal();
  }
};
document.addEventListener('propagation-update', handlePropagationUpdate);
```

### Отрисовка рёбер

В `columnLineageEdges.js` добавлена функция:

```javascript
export function drawPropagationEdges(ctx) {
  // Отрисовка пунктирных фиолетовых рёбер для пропагированных колонок
}
```

### Подсветка при выборе колонки

Пропагированные колонки и рёбра проброса участвуют в общей трассировке
подсветки (`traceLineage` в `columnLineageGraph.js`):

* `traceLineage` принимает опциональный 5-й параметр `propagationEdges`
  (массив `{parentTableId, childTableId, columnName, childColumnName?, uniqueId}`);
* фикс-поинт цикл: если в подсветку попал родитель колонки-копии (или сама
  копия), в `highlightedCols`/`highlightedLines` добавляются копия, родитель
  и ребро проброса, после чего трассировка продолжается от них транзитивно;
* ключ ребра в `highlightedLines` совпадает с `data-line-key` SVG-пути:
  `prop-<parentTableId>-<childTableId>-<columnname>`;
* **важно:** такие ключи не содержат `->`, поэтому оба сайта парсинга ключей
  в `columnLineageLayout.js` защищены guard'ом (иначе `split("->")` даёт
  `undefined` и TypeError ломает цепочку rAF в `updateHighlight`);
* клик по пропагированной колонке диспатчит bubbling-событие
  `cll-propagated-column-click` (`detail: {tableId, columnName}`) — слушатель
  на `innerCanvas` в `columnLineage.js` запускает обычный `updateHighlight`;
* `updateLineStyles()` стилизует пути с `data-propagation="true"` отдельно
  от обычных: подсветка — `stroke-width: 6`, `opacity: 1` + класс `is-line-hl`
  (drop-shadow свечение); затухание — `stroke-width: 2.5`, `opacity: 0.25`.
  Фиолетовый пунктир сохраняется во всех состояниях;
* переключение фокусного режима (кнопка тулбара и ветка focus в
  `updateHighlight`) после `drawLines()` вызывает `drawPropagationEdgesLocal()`
  и `updateLineStyles()` — `drawLines()` очищает SVG целиком.

## События (Column Propagation)

### propagation-update

Вызывается при:
- Добавлении колонки
- Перемещении колонки
- Закрытии контекстного меню

**Данные события:**
```javascript
{
  detail: {
    uniqueId: string,    // ID вкладки
    reason: string,      // Причина: 'column-added', 'column-moved', 'menu-closed'
  }
}
```

### cll-propagated-column-click

Bubbling CustomEvent на пропагированной колонке. Слушатель на `innerCanvas`
(`columnLineage.js`) маршрутизирует его в `updateHighlight` — так клик по
копии подсвечивает родительскую цепочку.

**Данные события:**
```javascript
{
  detail: {
    tableId: string,     // ID таблицы-владельца копии
    columnName: string,  // Имя колонки
  }
}
```

## Производительность (Column Propagation)

- Состояние хранится в памяти (Map/Set)
- Нет повторных обходов графа
- Рёбра перерисовываются только при изменениях
- Cooldown 150мс между перемещениями колонок предотвращает избыточные обновления DOM

---

## Зоны повышенного риска (Column Propagation)

1. **Конфликт обработчиков событий** — contextmenu на колонках
2. **Утечка памяти** — неочищенные обработчики событий
3. **Несоответствие стилей** — использование существующих классов
4. **Проблемы z-index** — контекстное меню должно быть выше всего
5. **Неправильная маршрутизация рёбер** — использование существующего алгоритма

# Фича 2: «Протянуть таблицу в следующий слой»

## Цель

- Позволить пользователю быстро создать новую дочернюю таблицу, протянув существующую таблицу «вправо» жестом drag-and-drop за заголовок карточки
- Пользователь сам вводит название новой таблицы в поле ввода
- Обеспечить тот же функционал протягивания колонок, что и в фиче «Протянуть колонку», для вновь созданной таблицы

---

## UX-сценарий

1. Пользователь открывает полный режим Column Lineage для любой таблицы
2. Зажимает **левую кнопку мыши** на **заголовке карточки** таблицы (`.cll-header`)
3. Тянет мышь **вправо** более чем на пороговое расстояние (≥ 60 px)
4. Отпускает кнопку мыши
5. Появляется **диалог** с:
   - Полем ввода, куда пользователь **самостоятельно вводит имя новой таблицы** (формат `schema.table_name` или `db.schema.table_name`)
   - Чекбоксом **«Протянуть все колонки»** — по умолчанию включён
   - Если чекбокс отключён — в родительской таблице у каждой колонки появляются **чекбоксы** слева, позволяющие выбрать конкретные колонки
6. После подтверждения:
   - В граф Column Lineage добавляется **новая карточка-таблица** правее родительской
   - Выбранные колонки добавляются в новую карточку как пропагированные (фиолетовый стиль)
   - Для каждой добавленной колонки создаётся ребро связи (пунктирное фиолетовое)
   - Для новой карточки работает весь существующий функционал:
     - Кнопка «📜 Новый SQL» в заголовке
     - Drag-and-drop перемещение колонок
     - Редактирование алиаса колонки (✏️)
     - Удаление колонки (✕)
     - Просмотр модального окна с диффом SQL

---

## Условия для drag-инициации

Drag разрешён на любой карточке без предварительных проверок. Валидация происходит при подтверждении диалога:
- Поле имени не должно быть пустым
- Формат: минимум `table_name`, рекомендуется `schema.table_name` или `db.schema.table_name`

---

## Архитектура виртуальной таблицы

Новая таблица создаётся полностью в UI без обращения к backend.

### Структура объекта

```javascript
{
  // Полный ID в формате "db.schema.name"
  virtualTableId: string,

  // Метаданные для getTableInfo
  columns: [],           // заполняется по мере добавления колонок
  lineage: {
    upstream: [parentTableId],
    downstream: [],
  },
  sql_script: '',        // пустой — новая таблица
  sources: '',
  description: '',

  // Маркер: это виртуальная таблица, созданная через Table Propagation
  _isVirtual: true,
  _propagatedFrom: parentTableId,
}
```

Объект регистрируется в `window.__tablePropagationState.virtualTables` и инжектируется в `getTableInfo` через обёртку.

---

## Диалог создания таблицы

Диалог создаётся динамически в DOM при отпускании мыши.

### Элементы диалога

| Элемент | Описание |
|---------|----------|
| Поле ввода имени | Пустое, пользователь вводит `schema.table_name` или `db.schema.table_name` |
| Чекбокс «Протянуть все колонки» | По умолчанию `checked = true` |
| Список чекбоксов колонок | Виден только если основной чекбокс снят |
| Кнопка «Создать» | Подтверждает создание |
| Кнопка «Отмена» | Закрывает диалог без изменений |

### Поведение чекбоксов колонок

Когда чекбокс «Протянуть все колонки» **включён**:
- Список колонок скрыт
- Все колонки будут добавлены в новую таблицу

Когда чекбокс **выключен**:
- В карточке родительской таблицы у каждой колонки появляется чекбокс слева
- Пользователь может выбрать колонки кликом
- Диалог обновляется в реальном времени (показывает количество выбранных)

---

## Отображение новой карточки

Новая карточка размещается **правее родительской** в Column Lineage-панели:
- Позиция: `x = parentCardX + parentCardWidth + CARD_GAP`, `y = parentCardY`
- Карточка имеет тот же визуальный стиль, что и обычные карточки
- Заголовок имеет специальный класс `cll-virtual-table` для визуального отличия (пунктирная граница или иной индикатор)
- `onclick` заголовка не переходит к таблице (нет реального объекта в каталоге)

| `removePropagatedColumn(uniqueId, columnKey)` | Удаление |
| `promptColumnAlias(uniqueId, virtualTableId, colName, colEl)` | Редактирование алиаса |
| `updateTableCardSqlButtons(uniqueId, getTableInfo)` | SQL-кнопка в заголовке |
| `generateModifiedSql(virtualTableId, getTableInfo, uniqueId)` | Генерация SQL |
| `showSqlDiffModal(virtualTableId, uniqueId, getTableInfo)` | Модальное окно SQL |

### generateModifiedSql для виртуальной таблицы

Поскольку виртуальная таблица не имеет оригинального `sql_script`, `generateModifiedSql` генерирует скрипт **с нуля** по шаблону:

```sql
CREATE TABLE <virtualTableId> AS
SELECT
    <col1>,
    <col2 AS alias>
    ...
FROM <parentTableId>;
```

## Кнопка 🆔 и исходный id системы-источника (`_cd`)

В созданной (виртуальной) таблице при нажатии кнопки 🆔 на колонке в **первой
позиции** карточки, если **родительское поле называется `id`**, кроме обычного
суррогатного хэш-ID `<префикс>_id` дополнительно добавляется вторая колонка
`<префикс>_cd` — исходный `id` системы-источника из слоя ods
(`id::varchar AS <префикс>_cd`), с ребром проброса от колонки `id` родителя.

Реализация: `columnLineagePropagation.js` (`generateIdHashExpression`,
`isFirstColumnInCard`, `addSourceIdCopyColumn`) + `columnLineageEdges.js`
(`drawPropagationEdges`, поле `edgeInfo.childColumnName`).

## Производительность (Table Propagation)

- Drag-обработчики навешиваются только на заголовки (`.cll-header`), не на все колонки
- Ghost-элемент использует `transform`, а не изменение `top/left`
- Создание карточки виртуальной таблицы — один innerHTML insert

## Зоны повышенного риска (Table Propagation)

1. **Конфликт drag с pan/zoom** — Canvas Column Lineage уже поддерживает pan мышью; нужно корректное разграничение (drag за заголовок vs pan за пустую область)
2. **getTableInfo для виртуальных таблиц** — getTableInfo должна быть расширена, чтобы возвращать объекты из `__tablePropagationState.virtualTables`
3. **generateModifiedSql для пустого sql_script** — требует отдельной ветки генерации
4. **Неправильное позиционирование карточки** — координаты карточки зависят от текущего zoom/pan состояния canvas

## Проверка после изменений (Table Propagation)

Обязательно проверить:

1. ✅ Drag за заголовок → появление диалога при отпускании вправо
2. ✅ Drag влево / на малое расстояние → диалог не появляется
3. ✅ Диалог: поле имени пустое при открытии, пользователь вводит название
4. ✅ Диалог: чекбокс «все колонки» включён → все колонки добавляются
5. ✅ Диалог: чекбокс выключен → в родительской таблице появляются чекбоксы слева у колонок
6. ✅ Выбор отдельных колонок через чекбоксы
7. ✅ Создание карточки виртуальной таблицы правее родителя
8. ✅ Рёбра от родительской таблицы к виртуальной
9. ✅ Кнопка «📜 Новый SQL» в заголовке виртуальной таблицы
10. ✅ Модальное окно SQL с корректно сгенерированным INSERT
11. ✅ Drag-and-drop перемещение, редактирование алиаса, удаление колонки в виртуальной таблице
12. ✅ Pan/zoom не конфликтует с drag
13. ✅ Отсутствие регрессий в существующей Column Propagation
14. ✅ Обновление страницы → все виртуальные таблицы исчезают
