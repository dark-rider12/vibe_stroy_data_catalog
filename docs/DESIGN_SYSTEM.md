# DESIGN_SYSTEM.md

## Назначение

Документ фиксирует единую дизайн-систему каталога: какие важные изменения
визуальной консистентности уже внесены, и какие правила необходимо соблюдать
при любой будущей доработке интерфейса.

Документ обязателен к прочтению при любой работе с UI наравне с:

```text
docs/UI_RULES.md
```

# 1. Основные решения дизайн-системы

## 1.1. Палитра и CSS-переменные

Все цвета интерфейса задаются только через переменные в `:root` файла
`static/style.css`:

```css
:root {
    --primary-bg: #1E293B;  /* тёмный сайдбар */
    --accent-blue: #0055FF; /* основной синий акцент */
    --accent-green: #00D084;
    --text-dark: #0F172A;
    --text-gray: #64748B;
    --bg-main: #F8FAFC;     /* светлый фон приложения */
    --border: #E2E8F0;
    --grid-line: #CBD5E1;   /* вертикальные разделители колонок таблицы */
    --row-hover: rgba(0, 85, 255, 0.05); /* hover строки таблицы */
    --table-header-bg: #E0E7F0; /* фон строки заголовков таблицы */
    --white: #FFFFFF;
}
```

Запрещено хардкодить эти цвета в CSS-классах или в JS, если существует
соответствующая переменная.

## 1.2. Шрифты

Подключены через `@import` в начале `static/style.css`:

* `Inter` — весь интерфейсный текст;
* `JetBrains Mono` — весь код (SQL, выражения, имена колонок).

Правило: UI-текст всегда `'Inter', -apple-system, sans-serif`, код всегда
`'JetBrains Mono', Consolas, monospace`. Добавлять новые шрифты запрещено без
прямого запроса.

Исключения (намеренно оставлены):

* SVG-надписи анимированной схемы на главной (`src/ui/homeAnimation.js`) —
  SVG не подгружает Google Fonts, используется Arial;
* отдельный экспортируемый HTML-документ (`src/utils/helpers.js`) — это
  автономный файл без подключения шрифтов (Arial/Segoe UI/Courier New).

## 1.3. Карточки и панели

Единый паттерн для карточек/панелей/модалок:

```css
background: var(--white);
border: 1px solid var(--border);
border-radius: 12px;
```

Примеры: `search-item`, `welcome-description`, `doc-rules`, `meta-list li`,
`dq-card`, `fcm-dialog`, `exp-dialog`, `sql-diff-modal`, панели пропагации.

## 1.4. Оверлеи (модальные окна)

Все модальные оверлеи унифицированы:

```css
position: fixed;
inset: 0;
background: rgba(15, 23, 42, 0.55);
backdrop-filter: blur(3px);
z-index: 1000;
display: flex;
align-items: center;
justify-content: center;
padding: 20px;
```

Единая шкала слоёв:

* модальные оверлеи — `z-index: 1000`;
* нотификации (toast) — `z-index: 10000`;
* контекстные меню — `z-index: 10001`;
* плавающая панель подтверждения пропагации (`cll-col-select-panel`) —
  `z-index: 10004`.

## 1.5. Блоки кода

Все блоки кода светлые и выглядят одинаково (стиль вкладки «Скрипт»):

```css
background: var(--bg-main);
color: var(--text-dark);
border: 1px solid var(--border);
border-radius: 12px;
font-family: 'JetBrains Mono', Consolas, monospace;
```

К таким блокам относятся:

* вкладка «Скрипт» — `.ddl-block`;
* вкладка Data Quality — `.dq-code-box`;
* модальное окно «Новый SQL» — `.sql-diff-content`.

Запрещено создавать тёмные блоки кода (тёмный фон со светлым текстом) —
это было исправлено и возвращать такое не нужно.

## 1.6. Подсветка новых строк в sql-diff

В модале «Новый SQL» новые протянутые строки выделяются зелёным
(единственное исключение из светлого стиля — это выделение, не фон):

```css
.sql-diff-line--added {
    background: rgba(34, 197, 94, 0.15);
    border-left: 4px solid #22c55e;
    color: #166534;
    font-weight: 600;
}
```

Обычные строки — `.sql-diff-line` (тёмный текст на светлом фоне).

## 1.7. Акценты

В приложении сознательно используются несколько акцентов:

* синий `--accent-blue` — основной акцент приложения (ссылки, активные
  вкладки, hover иконок-кнопок);
* индиго (`#4F46E5`, `#3730A3`) — подсветка выбранной колонки и focus-кнопки
  Column Lineage;
* синий `#4F86F7` — выбранная карточка в Column Lineage (намеренно НЕ
  фиолетовый — возвращено по решению пользователя);
* фиолетовый (`#8b5cf6` → `#a855f7`) — только новые фичи пропагации
  (протягивание колонок/таблиц): кнопки, рёбра, чекбоксы, «Новый SQL»;
* маджента-градиент (`#c026d3` → `#a855f7` → `#7c3aed`) с кольцом-свечением
  `#e879f9` — выбранная (подсвеченная) пропагированная колонка
  (`.cll-column-propagated.is-selected`): намеренно ярче базового
  фиолетового градиента копии;
* свечение `#e879f9` (drop-shadow) на подсвеченном ребре проброса
  (`.cll-path-propagation.is-line-hl`, stroke-width 6) — состояние
  управляется из `updateLineStyles()`, не через CSS hover.

**Разные акценты — это осознанное решение пользователя.** Не унифицировать
их и не менять без прямого запроса.

## 1.8. Стили задаются классами, не инлайн

Все стили UI вынесены в `static/style.css`. В JS-модулях (`src/**`) запрещено
задавать оформление через `style.cssText`, `element.style.background` и т.п. —
только через CSS-классы.

Наименование классов:

* базовый класс — `.cll-prop-move-btn`, `.sql-diff-copy-btn`,
  `.cll-sql-view-btn`;
* варианты состояния — суффикс `--ok`/`--error`/`--muted`/`--added`
  (например `.cll-sql-view-btn--ok`, `.propagation-menu-message--error`,
  `.sql-diff-line--added`).

## 1.9. Таблица колонок (страница таблицы)

Современный light-стиль, единый с интерфейсом приложения:

* внешний контейнер — `.table-resize-wrapper`: `border: 1px solid var(--border)`,
  `border-radius: 10px`, `overflow: hidden`;
* шапка — заливка `var(--table-header-bg)`, текст `var(--text-dark)`,
  `font-weight: 700` (жирный чёрный); нижняя граница `var(--border)`;
* вертикальные разделители колонок — `var(--grid-line)` (тонкие, но хорошо
  различимые): они же служат визуальной зоной перетаскивания для изменения
  ширины колонок (`.col-resizer`);
* горизонтальные разделители строк — `var(--border)`; последняя строка без
  нижней границы;
* hover строки — `var(--row-hover)` (очень лёгкая голубая подсветка);
* чередование цветов строк не используется;
* имена полей — `font-weight: 600`, `var(--text-dark)`;
* SQL в «Алгоритме заполнения» и значения «Тип данных» — моноширинный шрифт
  (`JetBrains Mono`), без цветных badge/chip;
* кнопка Column Lineage в строке (`.col-lineage-btn`) — всегда видима
  (`opacity: 1`); сплошной синий фон `var(--accent-blue)`, белая иконка,
  hover — `#0044CC`, `:active` — scale 0.94, `:focus-visible` — синее
  кольцо; размер ~28×28px.

# 2. Правила доработки с консистентным дизайном

## 2.1. Общие правила

1. Новые элементы интерфейса обязаны соответствовать дизайн-системе из
   раздела 1.
2. Использовать только CSS-переменные из `:root`; при необходимости нового
   цвета — согласовать с пользователем.
3. Не добавлять новые шрифты, новые цветовые схемы и новые типы кнопок без
   запроса.
4. Переиспользовать существующие классы вместо создания почти одинаковых.
5. Оформление — только через классы в `static/style.css`. Никаких
   `style.cssText` и инлайн-`style` в шаблонах/JS (динамическое позиционирование
   `left`/`top`/`transform` — единственное допустимое исключение).

## 2.2. Новые модальные окна

Создавать по единому шаблону (`fcm-dialog`, `exp-dialog`, `sql-diff-modal`):

* оверлей — шаблон из раздела 1.4, `z-index: 1000`;
* диалог — `background: var(--white)`, `border-radius: 12px`,
  `box-shadow: 0 20px 40px rgba(0,0,0,0.25)` (или близко к этому);
* шапка — `background: var(--bg-main)`, нижняя граница `var(--border)`;
* код (если есть) — светлый блок по разделу 1.5.

## 2.3. Новые кнопки

* Primary-кнопки в новых фичах пропагации — фиолетовый градиент
  (`linear-gradient(135deg, #8b5cf6 0%, #a855f7 100%)`), единый для
  `.tpd-create-btn`, `.ccs-confirm-btn`, `.propagation-menu-btn`,
  `.sql-diff-copy-btn`.
* Кнопка «Новый SQL» в шапке карточки — только классы
  `.cll-sql-view-btn` + `.cll-sql-view-btn--ok` / `.cll-sql-view-btn--error`.
* Иконки-кнопки — единый паттерн: transparent, hover `#E2E8F0`, акцент
  `var(--accent-blue)`. Исключение — `.col-lineage-btn` (кнопка lineage в
  строке таблицы колонок): сплошная синяя заливка `var(--accent-blue)`,
  белая иконка, hover `#0044CC`, тень `rgba(0,85,255,.3)` — сделана
  явно кнопочной по запросу пользователя, чтобы не сливалась с текстом
  таблицы.

## 2.4. Известные несоответствия (не унифицировать без запроса)

На момент фиксации в приложении остались различия, которые НЕ трогать без
прямого запроса пользователя:

* primary-кнопки трёх цветов: синие (`.dq-copy-btn`, `.exp-submit-btn`,
  `.export-btn`), фиолетовые (пропагация), оранжевый/зелёный
  (`.fill-comments-btn`);
* focus-кольца: синие у старых контролов, фиолетовые у контролов пропагации;
* `.search-icon` — индиго `#4F46E5` в шапке поиска;
* акценты «выбранного» (раздел 1.7) — осознанные различия.

## 2.5. Проверка после изменений UI

После любой доработки UI проверить:

* вкладки и навигацию;
* поиск и его результаты;
* страницы таблиц (все вкладки: Колонки, Lineage, Скрипт, Data Quality,
  Column Lineage);
* модальные окна «Заполнить описания», «Экспорт», «Новый SQL»;
* контекстное меню пропагации и нотификации;
* согласованность шрифтов и переменных (нет новых хардкод-цветов).
