# LINEAGE_RULES.md

## Назначение

Lineage является критической подсистемой проекта.

Любое изменение должно сохранять корректность отображения происхождения данных.

---

# Перед изменением lineage

Обязательно прочитать:

* LINEAGE_ARCHITECTURE.md

Если задача связана с маршрутизацией связей:

* LINEAGE_ROUTING_ALGORITHM.md

Для быстрой проверки и тестирования графа:

* **[LINEAGE_TESTING_GUIDE.md](LINEAGE_TESTING_GUIDE.md)** — **РЕКОМЕНДУЕМЫЙ** способ: мгновенная математическая проверка геометрии, высот портов и отсутствия микроизломов в Node.js (`npm test`) без браузера.
* [BROWSER_GUIDE.md](BROWSER_GUIDE.md) — быстрый переход по прямому URL в браузере, открытие вкладки Lineage, ключевые селекторы (для визуальной и интерактивной приёмки).

---

# Основные режимы

Проект содержит:

* Table Lineage
* Column Lineage
* **Smart Execution Helper** (Режим пересборки DWH на Table Lineage) — см. [SMART_EXECUTION_HELPER.md](SMART_EXECUTION_HELPER.md)

Это независимые подсистемы.

Исправление одной не означает исправление другой.

---

# Критические требования

Никогда не ломать:

* отображение связей
* переходы по объектам
* upstream
* downstream
* focus mode
* поиск связанных объектов

---

# Что запрещено

Запрещено:

* удалять промежуточные связи
* скрывать реальные зависимости
* упрощать граф ценой потери информации
* менять направление потока данных

---

# Направление данных

Источник данных:

upstream

Потребитель данных:

downstream

Направление потока должно сохраняться во всех режимах.

# Проверка после изменений

1. **Регрессионная проверка алгоритмов геометрии (Node.js)**:
   * Выполнить `npm test` (или `npm run test:lineage`). Проверяет отсутствие микроизломов ($2\text{px} \le |\Delta| < 15\text{px}$) и сохранение строгой горизонтали связей на пакете ключевых графов. Подробнее: [LINEAGE_TESTING_GUIDE.md](LINEAGE_TESTING_GUIDE.md).

2. **Проверка в браузере (при изменении UI / интерактивности)**:
   * полный граф
   * focus mode
   * upstream / downstream
   * навигацию по таблицам и колонкам

---

# Производительность

Lineage может содержать десятки и сотни объектов.

Избегать:

* повторных обходов графа
* пересчета всего графа при локальных изменениях
* создания дубликатов структур данных

### Константы Sugiyama (Table Lineage)

Адаптивная настройка layout в `renderLineageCore` (`src/lineage/tableLineage.js`):

* инициализации слоя 0 — адаптивные, максимум 20 штук (оригинал + реверс + перестановки);
* проходы forward/backward — 15;
* проходы sifting — 2 (оптимизация 2026-09, было 5);
* вес гравитации к родителю `SUGIYAMA_GRAVITY_WEIGHT` — 1.5 (Barycentric Gravity для соосности с Rule 18);
* подсчёт пересечений `countCrossings` — Fenwick (BIT), **O(m log m)** (оптимизация 2026-09, было O(m²)).

Менять эти значения только осознанно: время растёт сверхлинейно с размером графа.
Подробности и замерные цифры — в `docs/LINEAGE_ROUTING_ALGORITHM.md`.

# Если меняется layout
 
Дополнительно проверить:
 
* отсутствие наложений
* отсутствие пересечений через узлы
* корректность маршрутизации длинных связей
* корректность групповых связей
* выравнивание верхних входящих рёбер (Правило 18):
  - промежуточные узлы (имеющие родителей) **запрещено** сдвигать как источники;
  - у фан-аутов сдвигается только цель;
  - для транзитных входящих цепочек (через vnode) цель подтягивается к порту реального источника (`Rule18:TargetToTransitSource`);
  - для первой карточки слоя разрешён отрицательный margin до -32px;
  - для контроля геометрии и выявления изломов/блокировок использовать `window.__LINEAGE_DEBUG__` в консоли браузера (подробнее см. [BROWSER_GUIDE.md](BROWSER_GUIDE.md));
* сквозной транзит длинных цепочек (Правило 15 и 10):
  - применяется ко всем транзитным цепочкам (включая fan-out);
  - при соосности портов источника и цели ($|transitY - lastY| < 2\text{px}$) вся цепочка фиксируется в единую прямую горизонталь ($\Delta = 0$);
  - если прямая линия блокируется промежуточными таблицами, связь локально огибает препятствие через ближайший свободный зазор (`probe(a - 8)`, `probe(b + 8)`) без выноса на внешний периметр холста, защищая порядок портов и монотонность шин;
* дуги перескока (Правило 10.2):
  - при пересечении горизонтали с вертикальными связями формируются индивидуальные дуги перескока ($R = 5\text{px}$) над каждой пересекаемой линией.
 
Подробности реализации см. в LINEAGE_ROUTING_ALGORITHM.md.

## Column Lineage в фокусном режиме

При отображении column lineage в фокусном режиме:

* **Основная цепочка** (самый длинный путь через выбранную колонку, включая родителей и потомков) выравнивается по вертикали на одной прямой
* **Ответвления** (column lineage связи, не входящие в основную цепочку) смещаются вниз на 150px относительно прямой линии
* Линии к ответвлениям имеют изломы и не проходят насквозь через транзитные таблицы
* **Выравнивание в одном слое**: таблицы одного слоя **касаются друг друга гранями** (без зазора) **ТОЛЬКО**, если в **текущем слое больше таблиц**, чем в **следующем слое** (по направлению потока данных: upstream → downstream). Если количество таблиц в текущем слое **меньше или равно** количеству в следующем — между таблицами сохраняется **зазор 20px** для прямого хода рёбер

---

## Column Lineage в полном режиме

* Все колонки таблиц отображаются (не только связанные с выбранной)
* **Выравнивание в одном слое**:
  - Таблицы в одном слое **касаются друг друга** **ТОЛЬКО**, если в текущем слое **больше таблиц**, чем в следующем (по направлению потока данных)
  - Если количество таблиц **уменьшилось или осталось тем же** — между таблицами **зазор 20px**
  - Правило аналогично фокусному режиму, но применяется ко **всем** таблицам в графе

# Источник констант в «Системе источник»

Колонки, заполняемые константой или системной функцией без данных таблицы
(`CURRENT_DATE`, литералы, `NULL`), в том числе определённые в CTE, показывают
в поле «Система источник» прочерк «-».

Агрегатные и оконные функции (`COUNT(*)`, `MAX(...)`, `row_number() over(...)`)
зависят от данных таблицы — для них источник выводится реальный.

Реализация: `lineage/column_lineage.py`, `_resolve_cte_source` +
`_is_constant_expression`.
