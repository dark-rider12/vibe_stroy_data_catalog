# Руководство по тестированию Table Lineage (Node.js Runner)

## 📌 Назначение

Настоятельно **рекомендуемый способ тестирования** геометрических алгоритмов, маршрутизации связей, позиционирования и защиты от регрессий в подсистеме Table Lineage.

Вместо запуска тяжёлого headless-браузера тестирование выполняется непосредственно в среде **Node.js** через тестовый раннер [`tests/verify_lineages.js`](../tests/verify_lineages.js).

---

## ⚡ Преимущества перед браузерным тестированием

| Критерий | Node.js Runner (`npm test`) | Браузер (Subagent / Puppeteer) |
|---|---|---|
| **Скорость** | **~30–50 мс** на схему | **5–15 секунд** на страницу |
| **Точность** | **Математическая (субпиксельная)**: точный расчёт высот портов $sY, eY$ и дельты $\Delta$ в пикселях | Визуальная (микроизлом 1–2px легко не заметить на глаз/скриншоте) |
| **Регрессии** | Пакетная проверка 4–50 схем за **1–2 секунды** | Последовательный переход по URL, долгие ожидания рендера |
| **Диагностика** | Полный лог сдвигов, причин блокировок (`margin < -32px`, `gap < 4px`) | Только итоговая картинка без объяснения, какое правило заблокировало сдвиг |
| **Стабильность** | 100% воспроизводимость, не зависит от разрешения экрана и ОС | Зависит от шрифтов ОС, размера окна, масштабирования DPI |

## 🚀 Как запускать

### 1. Быстрый прогон стандартного набора (регрессионный сьют)
Выполняет сборку и прогон по 4 ключевым эталонным схемам с разными типами графов:
```bash
npm test
```
*(или `npm run test:lineage`)*

Стандартный набор проверяет:
1. `dm.core.account_card_overview` — длинные транзитные цепочки (Rule 15) и верхние транзитные входящие рёбра (Rule 18);
2. `dm.core.account_balance_dynamics` — строго горизонтальные одиночные связи слоёв 0→1;
3. `dm.core.unified_client_directory` — многослойный сложный граф с изолированными парами (Rule 2.3/16);
4. `dds.calc.account_card_contract` — смешанные fan-out и fan-in связи.

### 2. Проверка произвольной таблицы (или нескольких таблиц)
```bash
node tests/.run_test.cjs dm.core.account_card_overview
```
или для нескольких таблиц:
```bash
node tests/.run_test.cjs dm.core.account_card_overview dm.core.master_wide_join
```

> **Примечание:** Если изменялся исходный код в `src/` или `tests/`, перед запуском `node tests/.run_test.cjs` выполните сборку теста через `npm run test:lineage` (или соберите бандл `npm run build:js`).

## 🔬 Как устроен тестовый раннер

Файл: [`tests/verify_lineages.js`](../tests/verify_lineages.js)

1. **Боевые данные DWH**:
   Через встроенный модуль `vm` раннер подгружает реальный файл `dist/static/catalog.js` (все таблицы, метаданные и SQL-связи upstream/downstream).
2. **Прямой импорт ES-модулей**:
   Раннер вызывает реальные функции каталога:
   - `computeLayersAndVirtualNodes` + `optimizeSugiyamaLayout` (`src/lineage/tableLineageSugiyama.js`);
   - `applyPhase2Layout` + `alignStraightTopIncomingEdges` (`src/lineage/tableLineageLayout.js`);
   - `buildFinalPorts` + `applyStraightTransitChains` (`src/lineage/tableLineageEdges.js`).
3. **Модель DOM (Mock Layout)**:
   Эмулирует структуру колонок `.lineage-layer` со стандартным CSS flexbox-поведением:
   - межэлементный flex-зазор `gap: 35px`;
   - высота виртуальных узлов `32px` + margin `5px 0` ($42\text{px}$);
   - паддинги и высоты узлов в зависимости от связности (`getNodePaddingV`);
   - динамический `offsetTop = baseTop + marginTop`.
4. **Аудит каждого ребра**:
   Раннер рассчитывает координаты для каждого ребра:
   $$\Delta = eY - sY$$
   Классификация связей:
   - **Строго прямые связи**: $|\Delta| < 2\text{px}$ (идеальная горизонталь);
   - **Микроизломы**: $2\text{px} \le |\Delta| < 15\text{px}$ (**дефект**, требующий исправления!);
   - **Большие изгибы**: $|\Delta| \ge 15\text{px}$ (естественный переход между разными уровнями/слоями).

## 🚦 Интерпретация результатов

При успешном прохождении тестов код возвращает `0`:
```text
Всего рёбер: 17
Строго прямых связей (|Δ| < 2px): 8
Микроизломов (2px <= |Δ| < 15px): 0
Больших изгибов на другие уровни (|Δ| >= 15px): 9
======================================================
✓ ВСЕ ТЕСТЫ ПРОЙДЕНЫ УСПЕШНО: 0 МИКРОИЗЛОМОВ
======================================================
```

Если обнаружен паразитный микроизлом, тест завершается с кодом `1` и детально подсвечивает проблемное ребро:
```text
[ВНИМАНИЕ: МИКРОИЗЛОМ] dds.core.account_detail -> vnode-2 | sY=91 eY=88 Δ=-3px
======================================================
✗ ОБНАРУЖЕНЫ ДЕФЕКТЫ ГЕОМЕТРИИ: 1 МИКРОИЗЛОМОВ
======================================================
```

## 🎯 Когда всё же нужен браузер?

Тестирование через браузер ([`docs/BROWSER_GUIDE.md`](BROWSER_GUIDE.md)) остаётся необходимым для:
* визуальной оценки шрифтов, цветов и иконок;
* интерактивных сценариев: Pan & Zoom, перетаскивание холста мыши;
* кликов по узлам и рёбрам для проверки интерактивной подсветки цепочек связей (`tableLineageHighlight.js`).
