# SQL_OBFUSCATOR.md — Документация подсистемы AI-обфускатора и деобфускатора

## 1. Назначение подсистемы

Модуль предназначен для **локального обезличивания (шифрования)** чувствительных данных DWH (названий схем, таблиц, представлений, колонок, переменных, CTE и строковых констант) перед отправкой запросов и SQL в сторонние нейросети (LLM), а также для **обратной деобфускации (восстановления)** оригинальных названий из готового ответа нейросети.

**Ключевой принцип безопасности:**
* Работает **100% на клиенте** в браузере аналитика. Никакие данные, промпты или SQL не передаются на сторонние бэкенды или серверы.

## 4. Поддерживаемые диалекты SQL

Подсистема поддерживает выбор диалекта через радио-переключатель в шапке окна:

1. **`PostgreSQL` (выбран по умолчанию):**
   * Идентификаторы: двойные кавычки `"schema"."table"`.
   * Строки: стандартные `'...'`, экранированные `E'...'`, dollar-quoted `$$...$$`.
   * Защищённые функции и ключевые слова: `CURRENT_DATE`, `CURRENT_TIME`, `CURRENT_TIMESTAMP`, `LOCALTIME`, `LOCALTIMESTAMP`, `NOW()`, `DATE_TRUNC`, `DATE_PART`, `AGE`, `STRING_AGG`, `ARRAY_AGG`, `GENERATE_SERIES`, `ILIKE`, `RETURNING`, `JSONB`, `INTERVAL` и др.
2. **`MS SQL (T-SQL)`:**
   * Идентификаторы: квадратные скобки `[schema].[table]`, `[column]`.
   * Локальные и глобальные переменные: `@variable` $\to$ заменяется на `@OBJ_xxx`.
   * Временные таблицы: `#temp_table` $\to$ `#OBJ_xxx`, `##global_temp` $\to$ `##OBJ_xxx`.
   * Строки: стандартные `'...'` и юникод `N'...'`.
   * Защищённые конструкции и функции: `TOP`, `WITH (NOLOCK)`, `CROSS APPLY`, `OUTER APPLY`, `ISNULL`, `GETDATE()`, `SYSDATETIME()`, `DATEADD()`, `DATEDIFF()`, `CONVERT()`, `TRY_CONVERT()`, `IIF()`, `MERGE` и др.

## 5. Алгоритм обфускации и правила обработки

### 5.1. Источники терминов для замены
1. **Словарь DWH из `window.catalogData`**:
   Все базы, схемы, названия таблиц и физических колонок, уже загруженные в каталог.
2. **Локальный SQL-парсер (`extractSqlTerms`)**:
   Извлекает идентификаторы из самого SQL-запроса (CTE в секциях `WITH`, алиасы таблиц, вычисляемые поля, переменные `@var`, временные таблицы `#temp`).
3. **Промпт пользователя**:
   Любые латинские слова/идентификаторы (например, с подчёркиванием `deal_rk`, `fct_deals`) согласованно заменяются на те же самые токены, что и в SQL.

### 5.2. Формат токенов
* Идентификаторы (таблицы, схемы, поля, CTE, переменные): `OBJ_001`, `OBJ_002`, `OBJ_003`...
* Строковые константы SQL: `STR_001`, `STR_002`...

### 5.3. Защита от коллизий подстрок
* **Сортировка по длине по убыванию (`length descending`)**:  
  Термины заменяются строго от самых длинных к коротким (например, `fct_credit_deals` гарантированно заменится раньше, чем `credit_deals` или `deals`, а `deal_rk_hist` раньше, чем `deal_rk`).
* **Границы слов (`\b`)**:  
  Замена выполняется по регулярным выражениям с границами слов `\bterm\b` и флагом `gi`.

### 5.4. Строгие правила для дат, времени и интервалов
* **Даты и дату/время НЕЛЬЗЯ искажать!**
* Любые строковые литералы дат (`'2024-01-01'`, `'31.12.2024'`, `'2024-06-15 14:30:00'`) и интервалы (`'7 days'`, `'1 month'`) определяются функцией `isDateTimeString()` и защищаются специальными плейсхолдерами `___PRESERVED_DT_x___`.
* После замены идентификаторов даты возвращаются в исходном виде.
* Служебные слова дат (`current_date`, `now`, `day`, `days`, `month`, `year`) внесены в список защищённых ключевых слов и никогда не маскируются.

## 6. Алгоритм деобфускации (Восстановление)

* Функция `deobfuscateText(text, mapping)`:
  * Получает текст ответа нейросети и объект карты соответствий `mapping.tokenToOriginal`.
  * Сортирует токены по длине по убыванию.
  * Токены `STR_xxx` заменяются обратно на оригинальные строковые константы.
  * Токены `OBJ_xxx` заменяются с границами слов `\b` на оригинальные названия таблиц, схем, колонок и переменных.
  * Поиск токенов регистронезависим (на случай, если LLM изменила регистр токена на `obj_001`).

## 7. Модальное окно и UX

* Две вкладки:
  * **«1. Обезличить (Запрос к ИИ)»**:
    * Поле для промпта аналитика.
    * Поле для SQL.
    * Кнопка «⚡ Обезличить».
    * Чекбокс «Обезличивать строковые константы».
    * Блок результата с кнопкой быстрого копирования в 1 клик «📋 Скопировать всё для ИИ».
    * Сворачиваемая плашка «Таблица замен» со списком бейджей (`OBJ_001 ⇄ dds.fct_credit_deals`).
  * **«2. Восстановить (Ответ ИИ)»**:
    * Индикатор состояния сессионной памяти («✓ В памяти активно соответствий: N»).
    * Поле для вставки ответа LLM.
    * Кнопка «🔄 Восстановить названия».
    * Блок готового деобфусцированного кода с кнопкой «📋 Скопировать результат».
* Закрытие окна: клавиша `Escape`, клик вне окна (по оверлею) или повторное `Alt + O`.

## 8. Сборка и валидация при доработке

При внесении изменений в подсистему:

1. **Сборка JavaScript-бандла:**
   ```bash
   npm run build:js
   ```
   Команда компилирует `src/index.js` $\to$ `static/main.js` через `esbuild`, копирует бандл и стили в `dist/static/` и обновляет хэш кэша в `dist/index.html`.

2. **Проверка регрессий основного функционала каталога:**
   ```bash
   npm test
   ```
   Убедиться в отсутствии микроизломов в Lineage (должно быть `0 МИКРОИЗЛОМОВ`).

3. **Ручная проверка в браузере:**
   Открыть [`dist/index.html`](file:///c:/test/generate_catalog_gemini/dist/index.html) напрямую в браузере, нажать `Alt + O` и протестировать сценарии обоих диалектов.
